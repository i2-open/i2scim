# Decision Log - Java 25 Upgrade

This log tracks key decisions made during the upgrade to Java 25 and Quarkus 3.34.3. and diagnosis of other issues.  For each new issue start a new table.


| Date | Decision | Rationale |
| :--- | :--- | :--- |
| 2026-04-14 | Upgrade to Java 25 (LTS) | Support latest LTS, improve performance, and maintain security posture. |
| 2026-04-14 | Upgrade to Quarkus 3.34.3 | Latest stable version (as of April 2026) with Jakarta EE 11 support. |
| 2026-04-14 | Migrate to Apache HttpClient 5.4.1 | Address CVEs in older 4.5.x versions and align with modern standards. |
| 2026-04-14 | Update Jose4j to 0.9.6+ | Fix known JWE decompression DoS vulnerability. |
| 2026-04-14 | Use eclipse-temurin:25 as base image | Standardize on Temurin distribution for Java 25. |
| 2026-04-14 | Migrate to Micrometer Metrics | Replace deprecated SmallRye Metrics (MicroProfile) with recommended Micrometer for Quarkus 3.x. |
| 2026-04-14 | Reorder POM Tags | Ensure `<modelVersion>` is the first child of `<project>` to fix "invalid POM" resolution issues in submodules. |
| 2026-04-14 | Standardize Test Exceptions | Use `throws Exception` in JUnit tests to simplify handling of HttpClient 5 checked exceptions. |
| 2026-04-15 | Disable Polling Retries on Shutdown | Prevent long delays during test cleanup and profile switching when the target server is already down. |
| 2026-04-15 | Standardize on RESTEasy Reactive | Resolved Quarkus capability conflict in `pkg-i2scim-prov-mongodb` by replacing Classic RESTEasy with RESTEasy Reactive (`quarkus-rest-jackson`). |
| 2026-04-15 | Exclude K8S Load Tests | Explicitly excluded `LoadScimClusterTest` from the standard build to prevent stalls caused by connection attempts to non-existent cluster endpoints. |
| 2026-04-15 | Fix Race in `PollStream` | Resolved `ConcurrentModificationException` in `PollStream.pollEvents` by using `CopyOnWriteArrayList` for tracking acknowledgments and pending operations in `SignalsEventHandler`, and reduced initialization sleep during tests to prevent stalls. |
| 2026-04-15 | Switch JVM base image to `cgr.dev/chainguard/jre` | Replaced `eclipse-temurin:25-jre-alpine` (3 High CVEs from libpng) and `eclipse-temurin:25-jdk` (full JDK, ~21 CVEs) across all three JVM Dockerfiles. Chainguard JRE is rebuilt daily from source on a minimal Wolfi base with ~0 known CVEs, includes SBOM and Sigstore provenance, and is free via Chainguard Catalog Starter. Changed `--chown` and `USER` to UID 65532 (Chainguard `nonroot`). Replaced `JAVA_OPTS` env var (unused by exec-form CMD) with `JAVA_TOOL_OPTIONS` (read natively by the JVM). Updated CMD to pass args to the image's `["java"]` ENTRYPOINT. |
| 2026-04-23 | Migrate back to `eclipse-temurin:21-jre-alpine` | User requirement to use Temurin. Fixed `CMD` to include `java` to prevent `__cacert_entrypoint.sh` from failing when trying to `exec` arguments starting with `-`. Maintained UID 65532 and `JAVA_TOOL_OPTIONS` for consistency. |
| 2026-04-23 | Upgrade Temurin to Java 25 | The project is compiled for Java 25, so `eclipse-temurin:21` was incompatible. Upgraded to `eclipse-temurin:25-jre-alpine`. |
| 2026-04-23 | Revert to Chainguard JRE | Reverted from `eclipse-temurin:25-jre-alpine` to `cgr.dev/chainguard/jre:latest` due to moderate CVEs reported in Temurin. Updated Dockerfiles with instructions on how to switch between distributions, noting that Chainguard requires argument-only `CMD` while Temurin requires the `java` command to be explicit. |
| 2026-05-04 | Collapse Maven structure from 10 modules to 3 | Only `i2scim-universal` was actually deployed — the per-backend packagings, `i2scim-prov-memory`, `i2scim-prov-mongo`, `i2scim-signals`, and `i2scim-tests` provided no runtime separation and forced root `mvn install` to fail without a `-N` workaround (submodules used `${i2scim.version}` to import dep versions before the parent was installed). Collapsed to `i2scim-core` + `i2scim-client` + `i2scim-server`. Provider/signals code merged into `i2scim-server`; canonical SCIM schemas live in `i2scim-core`. Dropped Maven Central publishing infra (release plugins, GPG signing, OSSRH staging) — restoration recipe captured in `docs/publishing.md`. Dropped three Dockerfile variants and the `quarkus-kubernetes` extension (only `i2scim-universal` was kept, retitled but same image name). Added OCI labels and an embedded CycloneDX SBOM at `/sbom/i2scim.cdx.json` to the Docker image, with SLSA provenance via `docker buildx --attest`. Version bumped to `0.10.0`. See PRD #52 (umbrella) and slices #53–#60 for the per-step rationale. |
| 2026-05-28 | Disable MongoDB Dev Services by default; enable per-profile, pinned to `mongo:8.0` | `quarkus-mongodb-client` is always on the classpath, so Dev Services defaulted to *on* and started a throwaway mongo container for **every** QuarkusTest — including the many MemoryProvider-backed tests (memory/signals/ssf/logging/opa) that never touch mongo — and risked starting in production. The `%test.…image-name=mongo:8.0` override was also dead: all mongo test profiles use a custom `getConfigProfile()` name, so `%test.`-prefixed properties never applied, and Dev Services silently fell back to `mongo:7.0` while the Testcontainers signals tests pinned `mongo:8.0` (two mongo images per run). Set `quarkus.mongodb.devservices.enabled=false` + unprefixed `image-name=mongo:8.0` in `application.properties`; the four MongoProvider-backed profiles (`ScimMongoTestProfile`, `ScimDevOpsTestProfile`, `ScimAuthTestProfile`, `ScimClientProfile`) re-enable it via `TestUtils.enableMongoDevServices()`. Result: a full run pulls ONE mongo image and starts mongo only where it's used. |
| 2026-05-28 | Share one `mongo:8.0` Testcontainers instance across the signals durability/store tests | `MongoPendingAckStoreTest`, `MongoPendingPushStoreTest`, and `SignalsDurabilityTest` each started and stopped their own `MongoDBContainer`. Replaced with `SharedMongoContainer` — a single `mongo:8.0` started once per JVM (surefire's default `reuseForks=true`) and reaped by ryuk on exit; each test uses a distinct DB name. Cuts three container starts to one and matches the Dev Services tag. |
| 2026-05-28 | Scope Docker test-cleanup to Testcontainers-labeled resources only | Added `scripts/docker-clean-tests.sh` as a safety net for runs killed before ryuk reaps (kill -9, IDE stop, CI timeout). It removes only `org.testcontainers=true`-labeled containers/networks/volumes plus dangling images, so docker-compose stacks (the local mongo cluster, goSignals, Keycloak, and unrelated projects) and tagged images are never touched. CI (`build-and-attest.yml`) sets `TESTCONTAINERS_RYUK_DISABLED` + `TESTCONTAINERS_CHECKS_DISABLE` since the runner is ephemeral. |
